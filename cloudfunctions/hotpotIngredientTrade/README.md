# Ingredient authority (source only; not deployed)

Run `node test.js`. Deployment requires the native client-callable CloudBase function `hotpotIngredientTrade`, environment variable `HOTPOT_PROFILE_ENVIRONMENT` matching the profile environment, and server-only database collection `hotpot_ingredient_trade_v1`. Deny all direct client database access. Do not expose HTTP, timer, or cross-function invocation. Account hashing matches hotpotProfileSync and uses only getWXContext.

All requests have protocolVersion 1, a fresh requestId (transport correlation), environment, action, and an immutable operationId for mutations. Retry a mutation with the same operationId and identical arguments. No balances, unlocks or client inventory are merged. Responses include status/error and, on success, the caller's snapshot. Sync takes pendingWins; selection takes selected/expectedRevision; consume takes tool 0..2; create takes tradeId/targetAccount/offeredId/receivedId; accept/reject/withdraw/getTrade take tradeId. Read and list need no operation ID. Lists are participant-scoped; creation is capped at 1024 lifetime requests per participant pending retention design.

Friend verification is intentionally unconfigured (`verifyFriend:null`). Create/accept fail with FriendVerificationUnavailable; a share return or caller-provided friendship flag is not evidence. Enable only after adding a trusted server verifier for both authenticated participant accounts. The Unity service exposes Unavailable, never simulates production exchange success. Its targetAccount constructor argument requires an authenticated friend selector; the current UI contract does not supply one.

Pending offline win timestamps are client-reported facts, checked for valid day, no future timestamp, and day/session deduplication. This provides server-authoritative random rewards and balances but is not server-side gameplay anti-cheat. A future authoritative victory verifier is necessary to prove offline gameplay. Existing historical profile wins are not imported automatically. Inventory and operation receipts are stored transactionally; receipts are retained rather than pruned unsafely.

Unity integration: construct WeChatIngredientTradeService(config, authenticatedAccount, collection.ApplyAuthoritativeSnapshot, new WeChatIngredientTradeBridge(), optionalTargetAccount). SyncAsync uploads only pending wins. SaveSelectionAsync uses the last server revision. ConsumeAsync must succeed before a production free-tool effect; do not independently decrement local and server inventories. Retrying after timeout reuses the operation ID because server transactions may already have committed. Reconstruct services on account/environment switches. No deployment, device test, friend proof, or release is implied by local diagnostics.
