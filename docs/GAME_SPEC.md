# Game Spec

> 只记录长期稳定、已经确认的游戏规则。未知内容写 `Not documented`，不要猜测。

## Product

- Working title: 火锅消消
- Genre: 参考 Fish Sort Puzzle 的点击式休闲整理解谜游戏。
- Target platform: 微信小游戏，竖屏、微信内独立运行。
- Engine and version: Unity 6000.0.26f1。
- Target session length: 5–7 分钟；单局倒计时为 10 分钟。
- Input method: 点击。玩家不使用拖拽；支持暂停、同日重试、退出、道具和广告/分享入口。
- Monetization: 以激励视频为主；提示、清空暂存和刷新盘面也允许以分享替代。第四口锅提前解锁只通过激励视频获得。
- Target audience: 微信休闲用户，重点面向女性用户及《羊了个羊》《抓大鹅》同类玩家。

## Player Promise

玩家在热闹的火锅桌上，从同平面碰撞、互不重叠的食材盘中找出目标食材，让食材爽快地下入对应火锅。玩家通过观察、取舍和清理盘面，体验整理、配对与连续完成订单的爽感。

## Core Loop

1. 观察当前订单小锅、暂存区和下方食材盘，找出可用的目标食材。
2. 点击露出的食材：匹配订单的食材飞入对应小锅；暂时不匹配的食材进入五格暂存小碟。
3. 三个同类食材完成一口锅，整锅端走并补入新订单；持续清理全部订单以通关。

## Core Rules

### Player

- 玩家只能点击当前可见且位于有效操作区域的食材；盘子之间不存在上下层遮挡；不支持拖拽操作。
- 匹配任一开启订单的食材自动选择可接收该食材的订单小锅并飞入锅中。
- 不匹配开启订单的食材进入暂存区。后续出现匹配订单时，暂存食材自动飞入对应小锅。
- 每口订单小锅需要 3 个同类食材；锅内食材沉入红汤，以订单牌中的 `1/3`、`2/3`、`3/3` 表示进度。
- 提示高亮一个当前可点击且匹配订单的食材，不自动代点；清空暂存将全部暂存食材组成一个混合盘追加到生成队列末尾；打乱仅重排当前剩余盘子位置，不改盘内内容或生成队列。每种道具均可通过激励视频或分享获得。
- 手动暂停、微信切到后台和观看激励视频期间，倒计时均停止。

### World / Board / Level

- 单局为正式的每日挑战玩法；每日内容和挑战状态必须可稳定复现。
- 当前交付仅为最高难度每日挑战 Unity 可玩版：初始 50 盘、183 食材单位、16 种，各种数量为 3 的倍数，共 61 单。清空暂存增加盘数，不增加食材或订单总量。
- 根据TASK-001的CL-020、CL-023/CL-024及v8 CL-050，当前固定采用骨架C全部50盘内容结构、逐盘数量、同类关系及配置顺序，使用挑战日期种子做全局一一食材映射，同日重试复现；A/B不轮换、不混合，不洗乱盘序。每0.2秒最多供给一个队首盘：盘面Y向下增大，任意有效在场盘中心Y<固定140则等待，等于140允许；空盘残影不阻挡供给。不补发积压次数，阻塞不改变队首、成功计数或出生随机流。成功盘按生成前计数在基础X=150/260间轮换，沿用独立水平偏移世界±0.5（盘面±50），只采样一次并缓存；中心出生Y=-radius-8，整个盘最下沿为-8，完整位于屏幕外。盘半径39/45/51/57/63不变。新刚体创建时一次施加当前坐标(0,+5) Force，保留持续向下力。允许依赖道具解围，不要求无道具可解；实现/验证状态以Task结果为准。
- 盘面视觉硬裁剪于暂存栏实际下沿（参考Y=292）至底部828，盘、食材、盘沿、残影和提示高光均受裁剪；订单、暂存、按钮和模态为前景。v8物理上边界内表面Y=-134，上墙中心-139/厚10，侧墙相应延长；左右0/420、底部828与打乱304…828保持。达到Y=140供给门槛不等于可见或可点。点击先由UI处理，裁剪外不能穿透，露出且alpha>0.1的像素可点击；隐藏目标不参与提示，奖励生效前再次验证，实际生效才扣分享额度。
- v8盘内按初始1–5份固定布局；食材组有效Alpha轮廓的最小包围圆直径相对整盘外沿直径为75%至85%，r013默认80%。允许同盘食材轻微压叠，每份保留约75%以上可见且不遮住主要识别特征，不越盘外沿。角度在-15°…+15°内按挑战种子、布局版本、plateId及itemId/sourceIndex独立键控确定，不消费核心或出生随机流；同日重试/回放一致，取走后不重排、放大或重抽。显示、Alpha命中、绘制层级和提示共享中心、尺寸与旋转；上层透明像素允许点中下层，订单和暂存图标端正。
- 北京时间每天 06:00 更新；当天可无限重试，退出不保存残局。每天首次通关计入累计通关次数。
- 进行中的对局跨06:00继续归属开局日，下一次开始或重试进入新挑战日；分享额度按发起领取时的挑战日期归属。
- 道具没有有效目标时禁止领取；激励或分享取消、失败不发奖也不扣额度，成功且道具实际生效才扣分享次数。
- 画面由上至下分为订单小锅区、五格暂存区和食材盘区。
- 食材盘位于下方，在同一平面自由碰撞，不设计上下堆叠；供给时允许暂态初始交叠并由物理分离。一个白瓷盘可以混放多种食材。
- 空盘在盘内食材全部取走后被收走。
- 初始开放两口订单小锅。完成订单数达到本局总订单数的 50% 时自动开启第三口锅；达到 80% 时自动开启第四口锅。
- 第四口锅可以在达到 80% 前通过激励视频提前解锁。
- 未解锁的第三、第四锅位始终可见，显示为未开火的传统铜锅；解锁后点火、出现蒸汽和订单牌。

### Enemies / Obstacles

- 盘子不互相遮挡；未进入可见操作区域的队列食材不可点击。
- 暂存区只有 5 个固定位置；玩家必须在暂存容量与当前订单之间做取舍。
- 本轮没有敌人单位。

### Progression / Economy

- 对局内进度由已完成订单数驱动，用于自动开启第三、第四订单锅位。
- 激励视频或分享可获得三种对局道具；激励视频可提前开启第四口锅。
- 当前不包含金币、体力、局外养成、关卡选择、图鉴或签到系统。
- 好友助力、组队和纪念品属于后续规划，具体规则为 `Not documented`。

### Win / Lose

- 当全部食材、订单和暂存项均结清时，玩家通关。
- 玩家点击一个无法进入任一订单的食材且五格暂存区已满时：若本局尚未成功复活，先进入一次复活机会并立即暂停倒计时、供给和盘面物理；若玩家拒绝、当前奖励请求取消/失败/不可用，或本局复活后再次溢出，才进入暂存满失败。复活成功继续同一局，不重置订单、盘面、时间或会话身份。
- 复活成功把五个暂存小碟中的全部食材按槽位顺序集中到同一只新混合大盘，严格追加普通供应队列末尾；食材不销毁、不复制。约0.8秒可见搬运结束前保持复活暂停，导致溢出的点击食材留在原大盘且不参与搬运；新盘随后只按普通队首规则进入盘面。
- 单局 10 分钟倒计时结束时，立即失败；不提供续时。

## Stable State Model

- 进入页 → 开始当日挑战 → 进行中 → 手动暂停 / 后台暂停 / 奖励暂停 / 复活等待与搬盘暂停 → 继续进行。
- 进行中食材的结果为：进入订单、进入暂存、从暂存自动进入订单，或在暂存已满时进入一次复活机会/失败。当前复活请求成功后的重复回调、重试或退出后的旧会话回调必须幂等忽略。
- 订单状态为：未开启、开启且收集 `0–2/3`、完成并端走、替换为新订单；第三、第四锅位还具有未开火等待解锁状态。
- 终局为通关、复活机会拒绝/失败或已用后的暂存溢出失败、倒计时失败；终局后允许同日重试或退出。

## UX and Input Principles

- 所有可点击食材必须通过空间位置、细描边和与背景的对比保持可辨识。
- 点击响应必须明确表达去向：入锅、进入暂存或失败原因。
- 订单牌始终显示目标食材图标和数字计数0/3、1/3、2/3、3/3，替代圆点进度，避免要求玩家记忆订单。
- 暂存区的五个白瓷小碟必须清楚表达容量、占用和自动转移。
- 订单完成应形成连续反馈：整锅端走、新锅出现和下一目标可见。

## Platform Constraints

- 必须适配微信小游戏竖屏与真实安全区。
- 跨设备存档方向采用微信云开发；当前 Unity 交付仅实现接口，不接真实云数据。
- 分享和开放数据域好友榜当前仅做接口与开发模拟。分享主题图只用于奖励分享替代流程，不作为普通通关或失败结算入口；全服排行榜不在当前交付范围。
- 排行依据为累计每日首通次数；当天重复通关不重复计数。
- 当前无广告位 ID，采用开发模拟激励；提示、清空暂存、打乱和复活共用每天三次分享替代额度。首次立即可用；第一次成功且效果实际生效后5分钟开放第二次，第二次成功生效后15分钟开放第三次，北京时间06:00重置。复活弹窗一次只显示一个奖励入口：分享已解锁时优先分享，否则显示模拟广告；广告不消耗分享次数。
- 微信社交/助力的具体服务接口、反作弊与数据保留策略为 `Not documented`。

## Confirmed Non-goals

- 不支持拖拽选取食材。
- 当前版本不包含金币、体力、局外成长、图鉴、签到或关卡选择。
- 当前版本不包含敌人单位。
- 倒计时结束后不提供续时。
