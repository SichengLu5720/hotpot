# 项目导航工作手册

## 适用与必要输入

用于创建或维护轻量项目导航。输入为当前工作包、相关变更、已有导航和经过检查的实际代码/资源/检查入口。按需读取相关 SPEC；不要为了补导航遍历整个项目。

导航回答“从哪里开始修改和检查”，不记录完整实现、产品规则、制作步骤或任务进度。上述内容分别留在代码、SPEC、工作手册和 Task。

## 收录标准与粒度

判断：Agent 修改此模块时，是否需要一个独立入口才能快速找到相关代码、配置、资源和检查？需要则收录。能由上层模块入口直接找到的内容不另起一行。

每行只包含模块名、关键实现入口、配置/资源入口和相关检查入口；按需链接已有文档、Figma 组件或主题配置，不复制它们的内容。使用可定位的项目相对路径或已验证链接，避免易变行号。不要维护文件大小、所有源文件职责或完整依赖图。

### 活动模块示例（收录示例，不表示项目已实现）

- 有活动管理器、统一活动入口与配置注册表时，导航收录“活动系统”，指向这些实际入口。
- 签到、限时挑战、节日活动共用框架时，通过活动配置/注册表定位，不为每种活动重复列一行。
- 某活动有独立玩法和实现，需要单独定位时，增列该活动的关键入口。
- 仅新增活动配置、换皮或调整奖励数值，且现有导航入口仍有效时，不更新导航。
- 活动开放规则、奖励和重复领取限制属于对应 SPEC；活动制作进度属于 Task。导航只链接，不复写。

## 更新触发

仅在以下情况更新：

1. 新增或移除需要独立定位的模块。
2. 关键实现、配置、资源来源或检查入口新增、迁移、替换或失效。
3. 实际工作反复定位错误或难以查找，需要补充或澄清入口。

普通内部修改、新增辅助文件、参数调整不自动触发；如果同时改变关键入口，则按入口变化处理。不要为了表示检查过而改日期、重排表格或新增日志。

## AI 维护步骤与所有权

1. 开工按模块查导航，并核对与本次工作相关的实际路径和入口职责；发现过期信息时，以实际实现定位，随后修订导航。
2. 完成本次修改后，按上述触发条件判断是否有导航变化。
3. 单一工作包且具有导航写入权时直接修改受影响行；并行时各 Agent 只向主任务返回建议行及依据，指定 Integrator 统一串行写入。没有写入权时不得自行修改共享文件。
4. 必要时首次创建轻量导航，但只收录本次已验证的模块；不补写猜测的模块或占位入口。沿用已有同等文档，避免双份导航。
5. 检查受影响的路径、符号/场景与链接是否真实存在，并核对入口职责。检查脚本尚不存在时明确写“暂无自动检查”及已有人工检查入口，不伪造脚本或声称通过。
6. 在原 Task 结果中简述实际导航变化即可，不新增导航维护 Task、版本或历史台账。没有变化时无需单独记录。

涉及玩法规则变更、未知模块归属或范围争议时返回主任务；不得借导航维护修改产品决定或扩大实施范围。

## 完成条件

- 当前受影响模块能通过少量关键入口定位；不存在因本次变化引入的失效引用。
- 无全文件清单、重复产品规则、猜测实现或无关文档改动。
- 路径存在只证明可定位，不能替代职责核对、功能验证或用户验收。
- 不因维护导航增加全量 QA 或构建要求。项目级链接检查脚本可按需添加，不属于本手册已提供的能力。
