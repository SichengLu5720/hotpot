# TASK-002 presentation integration

Open Scenes/Gameplay.unity after the project baseline is provisioned. GameplayView builds native uGUI at runtime. It loads original independent food_00..15 and plate textures, never preview crops. Approved reference: .harness/previews/TASK-002/v005.

This checkout initially had no Unity project. The reference editor is 2022.3.62f2. The owning baseline task must provide ProjectSettings, Unity UI (com.unity.ugui), physics2d, imageconversion and text/font modules. These paths are outside this dispatch. Do not copy prototype game rules: game-data.json is provenance/reference data only and is not read by the view (its failOnFull differs from Daily SPEC).

The platform owner mounts GameplayView and calls Bind(IPresentationPort). PresentationPort.cs defines local transport DTOs, not K0 contracts. An adapter must map the real K0 contracts and copy immutable snapshot data. SessionAction maps only semantic actions, including RetrySameDay; the view never creates a date, seed, inventory, pending queue or result statistics. No default session is created. Until bound, the approved entry is visible and the button emits ActionRequested for bootstrap integration.

Supply: call ObserveSupply(center,radius) at the core's observation boundary. It reports bounds and occupied circles at current physical positions. The adapter/core owns cooldown, queue, admission, ID allocation and SupplyCommit. Only committed snapshot plates create Dynamic Rigidbody2D bodies. Physics2D resolves plate/plate, side-wall and floor contacts. Per-body downward force, damping and a low-bounce contact material implement entering, falling and settling without changing global gravity or project settings. Item colliders are triggers used for picking; only plate rims contribute contact geometry. Board units are scaled by .01 for physics, and each mounted view has its own spatial island.

ViewPlate.motion is an optional view-local presentation hint, not a K0 contract. Default first appearance enters at (clamped snapshot x, 304 + radius); physics settles toward the floor/other plates. The snapshot x/y remain an authoritative correction checkpoint. motion.hasSpawnPosition supplies an explicit supply origin. motion.animateEntry=false restores directly at snapshot x/y (e.g. reconnect). For an existing plate, a changed snapshot x/y or changed motion.correctionRevision teleports to that checkpoint and resets velocity; unchanged coordinates preserve falling/settling across item transactions. Increase correctionRevision to reset to the same checkpoint. Adapter should send a new snapshot object instead of mutating an already delivered DTO. A new sessionId clears all bodies/remnants. UI visual transforms, picking and supply observation read the same current Rigidbody2D positions.

Removed items disable colliders immediately; removed/empty plates disable collision and leave occupied capacity before deferred destruction. A short collider-free plate fade/shrink remains purely visual. Foreground, hidden-view and session phase control body simulation; paused/terminal views do not keep falling. No timer here consumes queue entries or awards inventory. Force/damping/fade constants are presentation choices, not acceptance thresholds or core cooldowns.

Input: screen pixels use SetViewport(Rect) (bottom-left origin) or Screen.safeArea fallback. A platform adapter must supply actual WeChat safeArea. UI raycasts run before item overlap queries. Top opaque plate/rim blocks lower targets. The adapter must acknowledge rejected/no-state-change commands with AcknowledgeTap(itemId); accepted updates clear pending input via Apply. Input IDs are stable strings, never inferred from food identity.

Apply(ViewUpdate) consumes monotonic event sequence/transaction observations and immediately reconciles the final authoritative snapshot. No animation consumes RNG or changes inventory. Fixed buffer array indices are never compacted. Overflow comes exclusively from ViewPhase.Overflow; five non-null slots do not infer failure. Aborted has its own view. Results display only supplied ViewFact values. Snapshot arrays must be non-null; order slots are 0..3, buffer length is 5, item IDs unique and food IDs 0..15.

DevelopmentPresentationPort is an explicitly attached editor/development fixture with Publish(snapshot), ActionObserved, TapObserved and SupplyObserved. It is absent from the scene and does not implement core gameplay or fabricate session outcomes. Publish is disabled in production.

Bind an approved CJK Font via playerFont for deterministic device text. OS CJK font fallback is development convenience, not verified WeChat font delivery. Entry has only hero art and “开始下火锅”; no title, cards or guide text. Other flow pages retain required facts. Font embedding, real core/platform binding, physical simulation behavior, device rendering, touch, lifecycle and complete gameplay are not yet verified in Unity.
