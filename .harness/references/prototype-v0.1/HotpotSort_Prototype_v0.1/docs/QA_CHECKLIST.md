## 本机执行

工程根目录：

```bash
node tests/test_core.cjs
python tools/build_standalone.py
python tests/test_browser.py
```

浏览器测试依赖 Playwright，只是开发依赖。报告记录实际浏览器版本与测试注入方式；不是截图比对伪装成运行测试。

Unity：打开工程，进入 `Hotpot > Run Core Validation`。运行成功才会生成 `qa/unity-validation.json`。生成前该文件不应存在，不要手工写一个 `passed=true`。

## 人工试玩任务

第一局使用 A/seed7，先观察玩家能否理解单件点击及暂存自动吸收，不开启调试提示。第二局切换两种失败模式，记录玩家对第五格的预期是否符合规则。第三局分别试玩 B/C，记录是否因供给拥挤而无法接触目标，还是目标策略选出了需要更多周转的类别。

发现停滞时导出日志，区分：内容预留错误、物理供给堵塞、命中遮挡、目标成本近似不合理、玩家选择导致的暂存占用。不在没有记录时直接修改随机权重。

## 修复时必须重新跑的回归

改变补单逻辑后重跑逻辑通关、随机不变量和回放；改变盘子尺寸/生成点后重跑有限供给、命中和完整局；改变输入/动画后重跑快速重复点击与终局弹窗；改变公共数据后重跑三件倍数与开局目标。

跨端规则更改必须同步 C# 和 JavaScript，再在真实 Unity Editor 中跑 golden 校验。网页通过不自动等于 Unity 通过。
